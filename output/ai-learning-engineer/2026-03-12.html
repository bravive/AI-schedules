Session 2 of 5 — Self-Attention Mechanism: The Mathematical Trick
2 / 5

🔄 Where We Left Off

In Session 1, we built a bigram language model that predicts the next character using only the current character. It works, but it has a fatal limitation: it has no memory. It cannot look at context. The word "the" is easy for a human to predict mid-sentence, but our bigram model has no idea what came before the current letter.

Today we fix that. We learn self-attention — the mechanism that lets a model look at all previous tokens and decide which ones are relevant for predicting the next one. This is the single most important idea in the transformer architecture.

📚 Prerequisites Explained

Vectors and Embeddings (Recap)

A vector is a list of numbers that represents something. In our model, each token is represented by a vector (its embedding). Think of a vector as GPS coordinates in "meaning space" — tokens with similar meanings end up with similar coordinates. A vector like [0.2, -0.5, 1.3, 0.8] is a 4-dimensional embedding: four numbers that together capture something about that token's identity.

import torch
# A token's embedding is just a vector of numbers
token_embedding = torch.tensor([0.2, -0.5, 1.3, 0.8])
print(token_embedding.shape)  # torch.Size([4]) — a 4-dimensional vector
Dot Product — Measuring Similarity

The dot product of two vectors tells you how similar they are. Multiply corresponding elements, then sum the results. If two vectors point in the same direction, their dot product is large and positive. If they point in opposite directions, it is large and negative. If they are unrelated (perpendicular), it is near zero.

Analogy: Imagine two people pointing flashlights. If they point in the same direction, the dot product is high (they agree). If they point in opposite directions, the dot product is very negative (they disagree). If one points north and the other east, the dot product is zero (unrelated).

a = torch.tensor([1.0, 2.0, 3.0])
b = torch.tensor([4.0, 5.0, 6.0])

# Dot product: (1*4) + (2*5) + (3*6) = 4 + 10 + 18 = 32
dot = torch.dot(a, b)  # tensor(32.)

# High dot product = these vectors are "similar" / pointing same way
Matrix Multiplication — Many Dot Products at Once

Matrix multiplication is just doing many dot products in parallel. When you multiply matrix A (shape T x d) by matrix B (shape d x T), each entry in the result is the dot product of a row from A with a column from B. This is how attention computes the similarity between every pair of tokens at once.

# Q has shape (T, d) — each row is one token's query vector
# K has shape (T, d) — each row is one token's key vector
# Q @ K.T gives a (T, T) matrix of all pairwise dot products
Q = torch.randn(4, 8)   # 4 tokens, 8-dim queries
K = torch.randn(4, 8)   # 4 tokens, 8-dim keys
scores = Q @ K.T         # (4, 4) — token i's affinity for token j
Softmax — Turning Scores into Probabilities

Softmax takes a list of raw numbers and converts them into probabilities that sum to 1.0. It exponentiates each number (making them all positive), then divides each by the total. Larger inputs get disproportionately larger probabilities — softmax is "winner-take-more."

import torch.nn.functional as F

scores = torch.tensor([2.0, 1.0, 0.1])
weights = F.softmax(scores, dim=-1)
print(weights)  # tensor([0.6590, 0.2424, 0.0986])
print(weights.sum())  # tensor(1.0) — always sums to 1
Masking — Hiding the Future

In language generation, a token should only look at tokens that came before it, never tokens that come after. That would be cheating — like reading the answer before answering the question. Masking sets certain values to negative infinity before softmax, which forces those positions to become zero probability. This is called causal masking or an autoregressive mask.

# Lower-triangular mask: 1s below/on diagonal, 0s above
T = 4
mask = torch.tril(torch.ones(T, T))
# tensor([[1, 0, 0, 0],
#         [1, 1, 0, 0],
#         [1, 1, 1, 0],
#         [1, 1, 1, 1]])
# Token 0 can only see itself; token 3 can see all 4 tokens

📖 Glossary of Key Terms

Attention A mechanism that lets each token look at other tokens and compute a weighted combination of their information. The weights are learned, not fixed — the model decides what to pay attention to.
Causal Mask A triangular matrix that prevents tokens from attending to future positions. Ensures the model can only use past context for prediction, preserving the autoregressive property.
Dot Product A mathematical operation that multiplies corresponding elements of two vectors and sums the results. Used in attention to measure how relevant one token is to another.
Key (K) A learned projection of a token's embedding that answers: "What information do I contain?" Keys are compared against queries via dot product to determine attention weights.
Query (Q) A learned projection of a token's embedding that answers: "What am I looking for?" Each token broadcasts a query that is compared against all available keys.
Scaled Dot-Product The dot product divided by the square root of the key dimension. Prevents the dot products from growing too large, which would cause softmax to produce near-one-hot distributions and kill gradients.
Self-Attention Attention where the queries, keys, and values all come from the same sequence. Each token attends to other tokens in its own sequence (as opposed to cross-attention where they come from different sequences).
Softmax A function that converts a vector of raw scores into a probability distribution (non-negative values summing to 1). Used to normalize attention weights so they represent proportional relevance.
Value (V) A learned projection of a token's embedding that answers: "What information do I give if someone attends to me?" The final attention output is a weighted sum of value vectors.
Weighted Sum Adding up vectors, but each one is multiplied by a weight first. If token A has weight 0.7 and token B has weight 0.3, the result is mostly A's information with a little of B's mixed in.

🏫 Key Concepts: Self-Attention from First Principles

The Problem: Why Bigrams Are Not Enough

Our bigram model from Session 1 predicts the next character by looking at only the current character. But language depends on context. Consider: "The cat sat on the ___." A human easily guesses "mat" or "floor" because we use the entire sentence. A bigram model only sees "e" (the last character of "the") and has no idea a cat is involved.

What we need is a way for each token to gather information from previous tokens. The simplest version: just average all the previous token embeddings together.

# Naive approach: for each token, average all previous embeddings
# x has shape (B, T, C) — batch, time, channels
T = x.shape[1]
xbow = torch.zeros_like(x)  # "bag of words"
for t in range(T):
    xbow[:, t] = x[:, :t+1].mean(dim=1)  # average tokens 0..t

# Problem: this treats ALL previous tokens equally.
# "The" is just as important as "cat" — but it shouldn't be!

This averaging approach is a start, but it treats every previous token as equally important. We want the model to learn which tokens matter more. That is exactly what self-attention does.

Concept 1: The Mathematical Trick — Weighted Aggregation with Matrix Multiply
Covered at ~47:00 in the video

The key insight: We can compute a running average of previous tokens using matrix multiplication instead of a for-loop. This is both faster (GPUs love matrix multiplication) and, crucially, allows us to make the weights learnable.

The analogy: Imagine you are writing a book report. Instead of re-reading the entire book every time you write a sentence, you have sticky notes on the most important pages. The "weights" are like how many sticky notes each page has — pages with more notes contribute more to your understanding.

import torch
import torch.nn.functional as F

T = 4  # sequence length (4 tokens)
# Step 1: Create a lower-triangular matrix of ones
tril = torch.tril(torch.ones(T, T))
# tensor([[1, 0, 0, 0],
#         [1, 1, 0, 0],
#         [1, 1, 1, 0],
#         [1, 1, 1, 1]])

# Step 2: Normalize each row to sum to 1 (uniform weights)
weights = tril / tril.sum(dim=1, keepdim=True)
# tensor([[1.00, 0.00, 0.00, 0.00],   # token 0: 100% itself
#         [0.50, 0.50, 0.00, 0.00],   # token 1: 50% each of 0,1
#         [0.33, 0.33, 0.33, 0.00],   # token 2: 33% each of 0,1,2
#         [0.25, 0.25, 0.25, 0.25]])  # token 3: 25% each of 0,1,2,3

# Step 3: Matrix multiply to compute weighted averages
x = torch.randn(1, T, 8)  # 4 tokens with 8-dim embeddings
xbow = weights @ x         # (T,T) @ (B,T,C) -> (B,T,C)
# Each token's output is now the average of itself and all previous tokens!

Why this matters: By changing the weights matrix, we can control exactly how much each token contributes to each other token's representation. Uniform weights give us a simple average. But what if we could learn the weights based on what the tokens actually contain? That is self-attention.

Concept 2: Query, Key, Value — The Three Roles Every Token Plays
Covered at ~1:00:00 in the video

The core idea: In self-attention, every token simultaneously plays three roles. It produces a Query ("What am I looking for?"), a Key ("What do I contain?"), and a Value ("What information do I provide?"). The Query of one token is compared against the Keys of all other tokens to decide who to pay attention to. Then the Values of the attended tokens are combined.

The analogy: Think of a library. You walk in with a question (your Query): "I need information about cats." Each book on the shelf has a label (its Key): "Cat Behavior", "Dog Training", "Feline Health", "Car Repair." You compare your question against every label. "Cat Behavior" and "Feline Health" match well (high dot product). "Car Repair" does not match (low dot product). You then read the matching books and combine their contents (their Values), weighting them by how relevant each label was to your question.

import torch
import torch.nn as nn

B, T, C = 1, 4, 8     # batch=1, 4 tokens, 8-dim embeddings
head_size = 16         # dimension of Q, K, V projections

x = torch.randn(B, T, C)

# Three separate linear projections — no bias for clarity
key   = nn.Linear(C, head_size, bias=False)
query = nn.Linear(C, head_size, bias=False)
value = nn.Linear(C, head_size, bias=False)

# Each token produces its own Q, K, V by projecting its embedding
k = key(x)    # (B, T, head_size) — what each token "contains"
q = query(x)  # (B, T, head_size) — what each token "wants"
v = value(x)  # (B, T, head_size) — what each token "offers"

# Q, K, V are just the same embedding transformed 3 different ways!
print(k.shape)  # torch.Size([1, 4, 16])

Common confusion: "Why not just use the raw embeddings?" Because the same token needs to represent different things in different contexts. The linear projections let the model learn separate representations for "what I'm looking for" vs. "what I contain" vs. "what I share." The word "bank" should produce a different Key when it means "river bank" vs. "financial bank" — and the learned projections make this possible.

Concept 3: Dot Product Similarity — Matching Queries to Keys
Covered at ~1:05:00 in the video

The mechanism: To figure out how much token i should attend to token j, we compute the dot product of token i's Query with token j's Key. A high dot product means "these tokens are relevant to each other." We compute ALL pairwise dot products at once using a single matrix multiplication.

# Compute attention scores: how relevant is token j to token i?
# q has shape (B, T, head_size), k has shape (B, T, head_size)
# We want a (B, T, T) matrix where entry [i,j] = dot(q_i, k_j)

weights = q @ k.transpose(-2, -1)  # (B, T, head_size) @ (B, head_size, T) -> (B, T, T)

# CRITICAL: scale by 1/sqrt(head_size)
weights = weights * head_size**-0.5

# Without scaling, the dot products can be very large (proportional to head_size).
# Large values cause softmax to produce near-one-hot distributions,
# which kills gradients and makes training unstable.

Why scale? If the key dimension is 64, the dot products will have variance around 64 — producing numbers like 50 or -40. When you feed numbers that large into softmax, the output becomes nearly one-hot (one value near 1.0, everything else near 0.0). The model becomes too "confident" and gradients vanish. Dividing by √64 = 8 brings the variance back to ~1, keeping softmax in a healthy gradient range.

Analogy: Imagine you are rating restaurants on a scale. If your scale goes 0-100, a restaurant with 95 completely dominates one with 90. But if you normalize to a 0-10 scale (divide by 10), the difference between 9.5 and 9.0 feels more proportional. Scaling prevents any single token from dominating too aggressively.

Concept 4: Softmax Normalization & Causal Masking
Covered at ~1:10:00 in the video

Two problems to solve:

  1. Normalization: Raw dot product scores can be any real number. We need weights between 0 and 1 that sum to 1 (a probability distribution) so we can take a meaningful weighted average. Softmax handles this.
  2. No peeking at the future: During language generation, token 3 must not attend to tokens 4, 5, 6... because those haven't been generated yet. We need to mask them out.
# weights has shape (B, T, T) — raw attention scores

# Step 1: Create a causal mask (lower triangular)
tril = torch.tril(torch.ones(T, T))
# tensor([[1, 0, 0, 0],
#         [1, 1, 0, 0],
#         [1, 1, 1, 0],
#         [1, 1, 1, 1]])

# Step 2: Set future positions to -infinity
weights = weights.masked_fill(tril == 0, float('-inf'))
# Before softmax, the matrix looks like:
# [[ 0.3, -inf, -inf, -inf],
#  [ 0.1,  0.7, -inf, -inf],
#  [-0.2,  0.4,  0.5, -inf],
#  [ 0.6, -0.1,  0.3,  0.8]]

# Step 3: Apply softmax — -inf becomes 0, rest becomes probabilities
weights = F.softmax(weights, dim=-1)
# Now each row sums to 1.0, and future positions have weight 0
# [[ 1.0,  0.0,  0.0,  0.0],   # token 0: only looks at itself
#  [ 0.35, 0.65, 0.0,  0.0],   # token 1: looks at 0 and 1
#  [ 0.22, 0.39, 0.39, 0.0],   # token 2: looks at 0, 1, 2
#  [ 0.28, 0.14, 0.21, 0.37]]  # token 3: looks at all 4

The elegant trick: Setting future positions to -inf before softmax is brilliant because e^(-inf) = 0. So softmax naturally zeros out those positions without needing any special case logic. The remaining positions redistribute to sum to 1.0 as if the future positions did not exist.

Analogy: Imagine you are in an exam hall. You can look at other students' work, but a physical divider blocks everyone sitting behind you. You can only see people ahead of you and beside you. The mask is that divider — it is not that the future tokens are hidden; it is that they literally do not exist from your perspective.

Concept 5: Masked Self-Attention — The Complete Picture
Covered at ~1:15:00 in the video

Now we combine everything into a single, complete self-attention head. This is the core building block of every transformer, including GPT, Claude, and every modern LLM.

class Head(nn.Module):
    """One head of self-attention."""

    def __init__(self, head_size):
        super().__init__()
        self.key   = nn.Linear(n_embd, head_size, bias=False)
        self.query = nn.Linear(n_embd, head_size, bias=False)
        self.value = nn.Linear(n_embd, head_size, bias=False)
        # register_buffer: not a parameter, but saved with the model
        self.register_buffer('tril', torch.tril(torch.ones(block_size, block_size)))

    def forward(self, x):
        B, T, C = x.shape

        # 1. Project embeddings into Q, K, V
        k = self.key(x)    # (B, T, head_size)
        q = self.query(x)  # (B, T, head_size)
        v = self.value(x)  # (B, T, head_size)

        # 2. Compute attention scores (affinities)
        wei = q @ k.transpose(-2, -1)        # (B, T, T)
        wei = wei * k.shape[-1]**-0.5        # scale

        # 3. Apply causal mask
        wei = wei.masked_fill(self.tril[:T, :T] == 0, float('-inf'))

        # 4. Normalize with softmax
        wei = F.softmax(wei, dim=-1)          # (B, T, T)

        # 5. Weighted aggregation of values
        out = wei @ v                          # (B, T, head_size)
        return out

Step by step through the forward pass:

  1. Project: Each token's embedding is projected into three separate spaces via learned linear layers, producing Q, K, and V vectors.
  2. Score: Every token's Query is dot-producted with every token's Key, giving a T×T matrix of "how much should I attend to you?" scores.
  3. Scale: Divide by √head_size to prevent softmax saturation.
  4. Mask: Zero out future positions by setting them to -inf.
  5. Normalize: Softmax converts scores to weights that sum to 1 per row.
  6. Aggregate: Multiply the attention weights by the Value matrix. Each token's output is now a weighted blend of all (allowed) tokens' value vectors.

The big picture analogy: Self-attention is like a cocktail party. Each person (token) arrives with three things: a name tag (Key) describing who they are, a question (Query) about what they want to discuss, and expertise (Value) they can share. Everyone scans everyone else's name tags, comparing them with their own question. You then spend most of your time talking to the people whose name tags match your question best, and you walk away with a weighted blend of everyone's expertise — mostly from the relevant people, with a little from everyone else.

🌟 Key Takeaways

  • ➣ Self-attention lets tokens communicate. Instead of each token being an island (like our bigram model), self-attention lets every token gather information from all the tokens that came before it, with learned weights that determine who matters most.
  • ➣ Query, Key, Value is a search engine. The Query asks "what am I looking for?", the Key says "here's what I contain," and the dot product between them measures relevance. The Value is the actual content that gets passed along. This Q/K/V pattern is the single most important architectural idea in modern AI.
  • ➣ Masking preserves causality. By setting future positions to negative infinity before softmax, we ensure the model never cheats by looking at tokens it hasn't generated yet. This is what makes the model autoregressive — it generates one token at a time, left to right.
  • ➣ Scaling prevents gradient death. Without dividing by √head_size, dot products grow large, softmax produces near-one-hot outputs, and gradients vanish. The scaling factor keeps everything in a numerically healthy range.
  • ★ Aha moment: Self-attention is just a fancy weighted average. Each token's output is a weighted sum of all (past) tokens' Value vectors. The weights are not fixed — they are dynamically computed based on the content of the tokens via the Q·K dot product. This is what makes transformers so powerful: the way information flows between tokens is content-dependent, not position-dependent.
