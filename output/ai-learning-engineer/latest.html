🎯 Session Focus

Introduction, Bigram Language Model & Tokenization Basics

This session covers the first ~23 minutes of the video (0:00 - 23:00). Karpathy sets up the entire project: what we're building, why, and the simplest possible language model as a starting point.

📚 Key Concepts Covered

1. What is a Language Model?

At 0:42, Karpathy defines the goal: a language model is a system that, given a sequence of characters (or tokens), predicts the next character. This is the core idea behind GPT, ChatGPT, and every modern LLM.

The key insight: language modeling is next-token prediction. The entire magic of GPT — from writing code to answering questions — emerges from training a model to predict the next token extremely well over enormous datasets.

Going deeper: This framing connects to Shannon's information theory (1948). The "entropy" of language — how predictable the next token is — is what language models learn to estimate. Lower perplexity = better model.

2. Character-Level Tokenization

At 3:14, Karpathy makes a deliberate choice: instead of using BPE (byte pair encoding) like real GPT models, he works at the character level. Every unique character in the training text gets a number.

chars = sorted(list(set(text)))
vocab_size = len(chars)  # 65 unique characters
stoi = {ch: i for i, ch in enumerate(chars)}  # string to int
itos = {i: ch for i, ch in enumerate(chars)}  # int to string
encode = lambda s: [stoi[c] for c in s]
decode = lambda l: ''.join([itos[i] for i in l])

Why character-level? It strips away the complexity of subword tokenization so you can focus on the model architecture. In production GPT, OpenAI uses ~50,000 BPE tokens; here we use 65 characters. Same principles, simpler vocabulary.

Real-world context: Understanding tokenization is critical. Token boundaries affect model performance — that's why GPT sometimes struggles with counting letters or arithmetic (tokens don't align with digit boundaries).

3. The Training Dataset: Tiny Shakespeare

At 2:22, Karpathy introduces the training data: the complete works of Shakespeare (~1MB of text, about 1 million characters). This is tiny by modern standards but perfect for learning.

Comparison to real GPT:

  • Tiny Shakespeare: ~1M characters, 65 vocab size
  • GPT-2: ~40GB of text (WebText), 50,257 vocab size
  • GPT-3: ~570GB of filtered text, 50,257 vocab size
  • GPT-4: estimated trillions of tokens, likely larger vocab

The beauty of this tutorial is that the architecture is identical — only the scale differs.

4. The Bigram Language Model

At 8:50, Karpathy builds the simplest possible language model: a bigram model. It predicts the next character based only on the previous character. No context beyond one token.

import torch
import torch.nn as nn
from torch.nn import functional as F

class BigramLanguageModel(nn.Module):
    def __init__(self, vocab_size):
        super().__init__()
        self.token_embedding_table = nn.Embedding(vocab_size, vocab_size)

    def forward(self, idx, targets=None):
        logits = self.token_embedding_table(idx)  # (B, T, C)
        if targets is None:
            loss = None
        else:
            B, T, C = logits.shape
            logits = logits.view(B*T, C)
            targets = targets.view(B*T)
            loss = F.cross_entropy(logits, targets)
        return logits, loss

    def generate(self, idx, max_new_tokens):
        for _ in range(max_new_tokens):
            logits, loss = self(idx)
            logits = logits[:, -1, :]  # last time step
            probs = F.softmax(logits, dim=-1)
            idx_next = torch.multinomial(probs, num_samples=1)
            idx = torch.cat((idx, idx_next), dim=1)
        return idx

Key insight at 12:30: The embedding table IS the model. Each row is a learned probability distribution over what character comes next. Row for 'h' might have high probability for 'e' (because "he", "the"). This is just a lookup table — no attention, no transformation.

Why start here: The bigram model produces garbage Shakespeare ("CEy lsjwP..."), but it establishes the training loop, loss function (cross-entropy), and generation method that will remain exactly the same as we scale up to the full transformer.

5. Cross-Entropy Loss & Training Loop

At 16:45, Karpathy explains the loss function. Cross-entropy loss measures how well the model's predicted probability distribution matches the actual next character.

The math: For a vocabulary of 65 characters, a random model would assign equal probability (1/65) to each. The expected loss is -ln(1/65) ≈ 4.17. If the initial loss is near 4.17, the model hasn't learned anything yet. As training progresses, loss decreases — the model is getting better at predicting the next character.

Training loop (19:20):

optimizer = torch.optim.AdamW(model.parameters(), lr=1e-3)

for steps in range(10000):
    xb, yb = get_batch('train')
    logits, loss = model(xb, yb)
    optimizer.zero_grad(set_to_none=True)
    loss.backward()
    optimizer.step()

This exact loop — forward pass, compute loss, backward pass, optimizer step — is used for the final GPT model too. Only the model inside changes.

Karpathy explains this is a companion video to the nanoGPT repository. The goal: reproduce GPT-2 (124M parameter version) from scratch. But first, build understanding from the ground up with a tiny model on a tiny dataset.

2:22 - 3:14 | Dataset setup

Downloads Tiny Shakespeare (~1MB). Shows that it's just raw text — all of Shakespeare's plays concatenated. Explores the character set: 65 unique characters including uppercase, lowercase, punctuation, and newlines.

3:14 - 8:50 | Tokenization & data preparation

Builds encode/decode functions. Creates train/val split (90%/10%). Introduces the concept of block_size (context length) — the maximum number of tokens the model looks at. For the bigram model, block_size=1 (only one previous character). Shows how a single training example actually contains block_size+1 examples within it (each position predicts the next).

8:50 - 16:45 | Building the bigram model

Creates the simplest possible neural network: a single embedding table. Input token index → lookup row → output logits for next token. No hidden layers, no attention, no positional encoding. The embedding table has shape (vocab_size, vocab_size) = (65, 65). Each of the 4,225 parameters is independently learned.

16:45 - 23:00 | Training & generation

Trains for 10,000 steps with AdamW optimizer. Loss drops from ~4.17 (random) to ~2.5. Generates text: it's still mostly nonsense, but you can see patterns emerging (common character pairs, some short words). This is the baseline we'll dramatically improve.

🛠 Practical Exercise

Build and Train the Bigram Model Yourself

Time: 20-30 minutes

  1. Set up: Open a Jupyter notebook or Google Colab. Download the Tiny Shakespeare dataset: wget https://raw.githubusercontent.com/karpathy/char-rnn/master/data/tinyshakespeare/input.txt
  2. Implement tokenization: Build the encode/decode functions from scratch. Print encoded text to verify.
  3. Build the BigramLanguageModel: Type the code yourself (don't copy-paste). Understand each line.
  4. Train for 10,000 steps: Plot the loss curve. Does it match what Karpathy shows (~4.17 → ~2.5)?
  5. Generate 500 characters: Compare your output to Karpathy's. Notice the character-pair patterns.
  6. Experiment: Try changing the learning rate (1e-2, 1e-4). Try training for 50,000 steps. Does the loss keep decreasing? Why or why not?

Bonus challenge: Can the bigram model ever produce the word "the" reliably? Why is it limited? (Hint: think about what information is available at each prediction step.)

🏆 Key Takeaways

  • Language modeling = next-token prediction. This single objective, scaled up, produces everything from autocomplete to GPT-4.
  • Tokenization maps text to numbers. Character-level is simplest; real models use BPE. Token boundaries matter for model performance.
  • The bigram model is a lookup table. It proves the training pipeline works, but it can only model single-character dependencies.
  • Cross-entropy loss measures prediction quality. Random = ~4.17 for 65-char vocab. Lower is better. This metric stays the same as models scale.
  • The training loop is universal. Forward, loss, backward, step. This exact pattern is used from the simplest to the largest models.
