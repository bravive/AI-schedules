📚 Prerequisites Explained

Python Basics

You need to be comfortable with Python: variables, loops, functions, lists, and dictionaries. Think of Python as the language we'll use to write our instructions to the computer. If you can write a function that takes a list of numbers and returns the sum, you're ready.

Tensor

A tensor is just a multi-dimensional array of numbers. A single number is a 0D tensor (a scalar). A list of numbers is a 1D tensor (a vector). A spreadsheet of numbers is a 2D tensor (a matrix). A stack of spreadsheets is a 3D tensor. That's it — tensors are just containers for numbers arranged in dimensions.

import torch
scalar = torch.tensor(42)          # 0D — a single number
vector = torch.tensor([1, 2, 3])   # 1D — a list
matrix = torch.tensor([[1,2],[3,4]])# 2D — a spreadsheet
PyTorch

PyTorch is a library (a toolkit) for doing math on tensors, especially on GPUs for speed. Think of it as a supercharged calculator designed for machine learning. It handles two key things: (1) fast math on tensors, and (2) automatically computing gradients (we'll cover gradients later). We'll use import torch throughout.

Character vs. Token

A character is a single letter, digit, or symbol: 'a', '7', '!'. A token is whatever unit we choose to feed into our model. In this session, we'll use characters as tokens — each character gets its own number. Real systems like GPT-4 use "subword tokens" (chunks of words), but characters keep things simple for learning.

Probability Distribution

Imagine you have a bag of colored marbles: 50% red, 30% blue, 20% green. That's a probability distribution — it tells you how likely each outcome is. The numbers must add up to 100% (or 1.0). In our model, we'll predict a probability distribution over the next character: maybe 40% chance it's 'e', 25% 'a', etc.

Loss Function

A loss function is a score that tells us how wrong our model is. Think of it like a golf score — lower is better. If our model predicts the next character should be 'z' but the actual next character is 'e', the loss will be high. If it correctly predicts 'e', the loss will be low. We use this score to improve the model.

📖 Glossary of Key Terms

Bigram A pair of consecutive items. A bigram model predicts the next character using only the current character. Like predicting what someone will say next based only on the last word they said.
Cross-Entropy Loss A specific loss function for classification. It heavily penalizes confident wrong predictions. If your model says "99% chance it's 'z'" but the answer is 'e', cross-entropy loss will be enormous.
Embedding Assigning each token a list of numbers (a vector) that represents its meaning. Like giving each word GPS coordinates in "meaning space" — similar words end up near each other.
Gradient A direction that tells us how to nudge each number in our model to reduce the loss. Like a compass pointing downhill — follow the gradient to make the model less wrong.
Logits Raw, unnormalized scores the model outputs before turning them into probabilities. Think of them as "votes" — higher logit = model thinks this option is more likely. We convert logits to probabilities using softmax.
Softmax A function that converts a list of raw numbers (logits) into probabilities that sum to 1.0. It exponentiates each number then divides by the total, so bigger numbers get bigger probabilities.
Token The smallest unit of text the model sees. In this session, each character is a token. In production models, tokens are usually chunks of words (subwords).
Training Loop The repeated cycle of: (1) feed data to model, (2) compute loss, (3) compute gradients, (4) update model weights. Each cycle makes the model slightly better, like practicing a skill over and over.

🏫 Key Concepts: Building a Bigram Language Model from Scratch

What Are We Learning and Why?

You know how autocomplete on your phone predicts the next word you'll type? That's exactly what we're building here, from scratch — except we'll start even simpler, predicting the next character.

Today we build a bigram language model. It's the simplest possible language model: given the current character, predict the next one. It's intentionally dumb — it only looks at one character at a time. But it introduces every fundamental concept we'll need when we build the full GPT transformer in later sessions.

Think of this session as building a bicycle before building a car. The bicycle teaches you about wheels, steering, and balance — concepts you'll need for the car too.

Concept 1: Tokenization — Turning Text into Numbers
Covered at ~3:00 in the video

The problem: Neural networks can only work with numbers, not text. So we need a way to convert every character into a number and back again.

The analogy: Imagine a secret codebook where each letter gets a number: A=0, B=1, C=2... That's tokenization. We build two dictionaries: one that converts characters to numbers (stoi — string to integer), and one that converts numbers back to characters (itos — integer to string).

The code:

# Get all unique characters from our training text
chars = sorted(list(set(text)))
vocab_size = len(chars)  # How many unique characters exist

# Build the lookup tables
stoi = {ch: i for i, ch in enumerate(chars)}  # 'a' -> 0, 'b' -> 1, etc.
itos = {i: ch for i, ch in enumerate(chars)}  # 0 -> 'a', 1 -> 'b', etc.

# Encode: turn a string into a list of integers
encode = lambda s: [stoi[c] for c in s]
# Decode: turn a list of integers back into a string
decode = lambda l: ''.join([itos[i] for i in l])

Line by line:

  • set(text) — removes duplicates, giving us each unique character once
  • sorted() — puts them in alphabetical order so the mapping is consistent
  • enumerate(chars) — pairs each character with its index: (0, 'a'), (1, 'b'), ...
  • stoi — dictionary comprehension that maps each character to its index number
  • encode — takes a string like "hello" and returns [7, 4, 11, 11, 14]
  • decode — takes [7, 4, 11, 11, 14] and returns "hello"

Why this matters: Every language model — GPT-4, Claude, Llama — starts with tokenization. The only difference is that production models use subword tokenizers (like BPE) that chunk words into pieces, while we use character-level for simplicity.

Concept 2: The Bigram Model — Predicting the Next Character
Covered at ~14:00 in the video

The idea: A bigram model looks at exactly one character and predicts what comes next. If it sees 'h', it might predict 'e' is likely (because "he" is common in English). If it sees 'q', it'll predict 'u' (because "qu" is extremely common).

The analogy: Imagine you're playing a word game where you can only see one letter at a time through a tiny window, and you have to guess the next letter. You'd learn patterns: after 't', 'h' is common. After 'q', 'u' is almost guaranteed. That's a bigram model.

How it works in code:

import torch
import torch.nn as nn

class BigramLanguageModel(nn.Module):
    def __init__(self, vocab_size):
        super().__init__()
        # Each token gets a row in this table.
        # That row contains the "votes" (logits) for what comes next.
        self.token_embedding_table = nn.Embedding(vocab_size, vocab_size)

    def forward(self, idx, targets=None):
        # idx is a (B, T) tensor of token indices
        # Look up the embedding for each token
        logits = self.token_embedding_table(idx)  # (B, T, C)

        if targets is None:
            loss = None
        else:
            B, T, C = logits.shape
            logits = logits.view(B*T, C)       # Reshape for cross-entropy
            targets = targets.view(B*T)         # Flatten targets too
            loss = F.cross_entropy(logits, targets)

        return logits, loss

Line by line:

  • nn.Embedding(vocab_size, vocab_size) — Creates a lookup table with one row per character. Each row has vocab_size numbers representing how likely each next character is. Initially these are random.
  • logits = self.token_embedding_table(idx) — For each input character, look up its row in the table. These raw scores are called "logits".
  • B, T, C — B = batch size (how many sequences at once), T = time/sequence length, C = channel/vocab size (number of possible next characters).
  • F.cross_entropy(logits, targets) — Compares our predictions to the actual next characters and computes how wrong we are.

Common confusion: "Why is the embedding table vocab_size x vocab_size?" Because for each of the vocab_size possible input characters, we need to output a score for each of the vocab_size possible next characters. It's like a big grid: rows = "what I see now", columns = "what I predict comes next".

Concept 3: Cross-Entropy Loss — Measuring How Wrong We Are
Covered at ~22:00 in the video

The intuition: We need a single number that captures "how bad are our predictions?" Cross-entropy loss does exactly this. It's designed for situations where the model outputs probabilities over multiple options (like predicting the next character from 65 possibilities).

The analogy: Imagine a weather forecaster. If they say "90% chance of rain" and it rains, they were good (low loss). If they say "5% chance of rain" and it rains, they were terribly wrong (high loss). Cross-entropy loss works the same way — it punishes confident wrong predictions much more than uncertain ones.

The math in plain English:

  1. Step 1: Take the logits (raw scores) and run them through softmax to get probabilities that sum to 1.0
  2. Step 2: Find the probability our model assigned to the correct answer
  3. Step 3: Take the negative log of that probability. -log(0.9) = 0.105 (good prediction, low loss), -log(0.01) = 4.6 (bad prediction, high loss)
  4. Step 4: Average across all predictions in the batch

What's a good loss value? At initialization (random weights), if we have 65 characters, the model assigns roughly equal probability to each: 1/65. The expected loss is -log(1/65) ≈ 4.17. If our trained model achieves a loss of, say, 2.5 — that's much better than random, though still far from perfect.

Concept 4: The Training Loop — Making the Model Learn
Covered at ~30:00 in the video

The big picture: Training is just a loop where we repeatedly: (1) show the model some data, (2) measure how wrong it is, (3) figure out which direction to nudge every number in the model to be less wrong, and (4) nudge them.

The analogy: Imagine learning to throw darts blindfolded. Someone tells you "you were 3 inches too far left and 1 inch too high." You adjust. Throw again. "1 inch too far right." Adjust again. Over thousands of throws, you get closer and closer to the bullseye. That's training.

optimizer = torch.optim.AdamW(model.parameters(), lr=1e-3)

for steps in range(10000):
    # 1. Get a random batch of training data
    xb, yb = get_batch('train')

    # 2. Forward pass: get predictions and loss
    logits, loss = model(xb, yb)

    # 3. Backward pass: compute gradients
    optimizer.zero_grad(set_to_none=True)  # Reset old gradients
    loss.backward()                         # Compute new gradients

    # 4. Update: nudge parameters to reduce loss
    optimizer.step()

Line by line:

  • AdamW(model.parameters(), lr=1e-3) — The optimizer. Adam is a smart gradient descent algorithm. lr=1e-3 is the learning rate: how big each nudge is. Too big = overshooting, too small = learning takes forever.
  • get_batch('train') — Grabs a random chunk of training data. xb is the input characters, yb is the target (next character for each input).
  • optimizer.zero_grad() — Clears gradients from the previous step. Without this, gradients would accumulate and give wrong directions.
  • loss.backward() — This is the magic. PyTorch automatically computes how every single number in the model should change to reduce the loss. This is called "backpropagation".
  • optimizer.step() — Actually applies those changes. Every number in the model gets nudged slightly in the direction that reduces the loss.

How this connects to real AI: GPT-4, Claude, and every large language model was trained with this exact same loop structure — just with billions of parameters instead of thousands, trained on terabytes of text instead of a small file, for weeks on thousands of GPUs instead of seconds on one.

Concept 5: Generating Text — Sampling from the Model
Covered at ~38:00 in the video

The idea: Once trained, we can generate text by repeatedly asking the model "given this character, what should come next?" and sampling from its probability distribution.

The analogy: Imagine a choose-your-own-adventure book, but at each page you roll weighted dice to pick the next page. Pages the model thinks are more likely get more sides of the dice. You keep rolling and following pages until you've generated a whole paragraph.

def generate(self, idx, max_new_tokens):
    for _ in range(max_new_tokens):
        # Get predictions for the current sequence
        logits, loss = self(idx)

        # Focus only on the LAST character's predictions
        logits = logits[:, -1, :]  # (B, C)

        # Convert logits to probabilities
        probs = F.softmax(logits, dim=-1)  # (B, C)

        # Randomly sample one character from the distribution
        idx_next = torch.multinomial(probs, num_samples=1)  # (B, 1)

        # Append the new character to our sequence
        idx = torch.cat((idx, idx_next), dim=1)  # (B, T+1)

    return idx

Line by line:

  • logits[:, -1, :] — We only care about the prediction for the last character in the sequence (the most recent one).
  • F.softmax(logits, dim=-1) — Converts raw scores into probabilities. If logits are [2.0, 1.0, 0.5], softmax might give [0.59, 0.24, 0.17].
  • torch.multinomial(probs, num_samples=1) — Randomly picks one index, weighted by probabilities. Higher probability = more likely to be picked. This randomness is what makes generated text different each time.
  • torch.cat((idx, idx_next), dim=1) — Appends the new character to the end of our sequence, then we loop again.

Why sampling and not just picking the highest probability? If we always picked the most likely next character, the output would be repetitive and boring. Sampling introduces variety — the model might pick a less likely but still plausible character, leading to more creative and diverse text.

🌟 Key Takeaways

  • ➣ Language models predict the next token. That's it. Whether it's a bigram model with 4,000 parameters or GPT-4 with 1.7 trillion, the core task is identical: given what came before, predict what comes next.
  • ➣ Tokenization converts text to numbers and back. Every AI model needs this bridge between human-readable text and math. Our character-level tokenizer is simple; production systems use subword tokenizers that are more efficient but work on the same principle.
  • ➣ The training loop is universal. Forward pass, compute loss, backward pass, update weights. This same 4-step cycle trains every neural network ever built — from our tiny bigram model to the largest frontier models.
  • ★ Aha moment: The bigram model's embedding table IS the entire model — it's literally a lookup table of "given character X, here are the scores for what comes next." The magic of transformers (coming in Session 2) is replacing this simple lookup with a mechanism that can look at ALL previous characters, not just the last one.
